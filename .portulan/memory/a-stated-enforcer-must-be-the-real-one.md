**type:** rule
**scope:** workspace — anyone writing down that something is required, forbidden, guaranteed, or impossible
**provenance:** `form=link` `href=../handoffs/2026-07-27-dependabot-security-and-the-watchers.md`
— 2026-07-27, the session that turned on Dependabot security updates and audited the platform floor, which
produced six instances of this in one day, in both directions.

When you write that something is required, forbidden, guaranteed, or impossible, **name the mechanism that
actually enforces it**, and be sure you read that mechanism rather than inferring it. A claim about
enforcement is a claim about a specific thing — branch protection, a ruleset, an App's permission set, an
organisation policy, or nothing at all except the document you are writing.

**Why it holds:** the failure has two signs and both mislead the same reader in the same way — they leave a
false model of what holds when nobody is watching. Both appeared on the same day.

- **Overstated.** Proposal `0006` shipped saying the three Dependabot settings "are Gated and an agent
  cannot perform them". Two of the three have `PUT` endpoints reachable by any admin-scoped token,
  including the maintainer's own credentials, which this repository already routes every commit through.
  What stops an agent is the **gate**, not the platform. The same conflation was then found three more
  times inside [`../gate-map.md`](../gate-map.md) itself — "**the maintainer**, by hand" of every Gated
  action, "the one step an agent cannot take" of re-pointing branch protection, and "the platform refuses
  it" of resolving a review thread, which was measured only for a GitHub App. That last gap closed on
  2026-07-27: `resolveReviewThread` **succeeds** with the maintainer's own credentials — once, on an admin
  account, saying nothing about a non-admin collaborator's token — so the row had been describing an App's
  permission set as if it were a property of the action.
- **Understated.** SHA-pinning every action was described for weeks as "this organisation's Actions
  policy" — wording that reads as a convention people comply with. `sha_pinning_required: true` is set at
  both organisation and repository level and the platform refuses an unpinned action outright. **A rail
  written down as a habit.**

Every drift this repository had caught before ran in the overstating direction, which is why the
understating one went unnoticed for so long: it does not look like a claim at all, it looks like modesty.
It is the same defect. Someone deciding whether they *may* use a movable tag reads etiquette where there is
a refusal, and someone deciding whether a guarantee will hold reads a promise where there is a habit.

There is a second cost specific to agents, and it is the one that bites: **an agent told something is
impossible does not ask permission for it**, because there is nothing to ask for. An overclaim of
impossibility silently deletes the gate it was trying to describe.

**When to apply:** at any sentence containing *cannot*, *must*, *is required*, *is forbidden*, *is
enforced*, *the platform refuses*. One question: **which mechanism, and did I read it?** If the honest
answer is "this document", say so — that is a real and common answer, and the gate map now says it in the
places where it is true. Prefer naming the mechanism over naming the outcome, because the mechanism is
checkable and the outcome is not.

**How this differs from the rules next to it.**
[`a-mandate-nothing-checks-is-already-broken.md`](a-mandate-nothing-checks-is-already-broken.md) governs a
rule adopted with no checker behind it.
[`a-checkers-coverage-is-measured-not-named.md`](a-checkers-coverage-is-measured-not-named.md) governs a
checker that runs, passes, and never looked. This one governs the sentence *describing* either — where the
enforcement may be entirely real and the description of it is wrong.

claim about what enforces something is generated by the thing that enforces it rather than written by hand.
