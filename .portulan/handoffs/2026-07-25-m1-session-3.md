Run 2 is the more interesting one. The `map` check had gone green, and the recipe then failed the
implementer's *own* new files for links to a handoff that did not exist yet — the rail catching the
person who built it, which is the only real evidence that it is a rail and not a decoration.

**Decisions + why.**

- **The workspace lives at `.portulan/` in this repository** — because the plan already declares this
  repo customer zero and `core/` is full of promises of the form "the workspace decides this" that had no
  instance behind them; and because milestone 2 derives the Workspace Definition from real content, which
  had to exist first. Alternatives considered: putting it in `examples/` (rejected — that is the fictional
  demo, a different reader), and deferring to milestone 2 (rejected — it would invert the plan's own
  "re-expression before schema" sequencing).
- **The demonstration task is a real defect, not a staged one** — because a self-chosen green task
  proves nothing. The undocumented `.claude-plugin/` entry was found independently by the session-open
  supervisor before any check existed, which is what made it usable as a genuine red.
- **The recipe checks tracked *and* untracked non-ignored paths** — because a map check that only sees
  committed directories passes on a new directory during exactly the window when the omission is being
  created.
- **Only one of the three checks enforces a rule this repository had already stated** — the kernel's line
  budget. Nothing here required relative links to resolve, or the README's map to be complete, until this
  session; those two rules were minted from the defect. Worth stating precisely, because the tidier claim
  — three existing rules gaining rails — would misdescribe what happened. The map rule came *out of* the
  incident, through the doctrine's own mistake → rule → rail loop, with the incident recorded so the rule
  can be retired later. Inventing rules to have something to check would have been the failure mode;
  deriving them from a real defect is the intended one.
- **`docs/vision.md` was not touched** — the constitution is human-owned. Where this session's findings
  bore on it, they went to the maintainer as questions.

**Decisions taken by the maintainer this session.**

- **The milestone-1 exit criterion was amended** — only the criterion row in
  [`../../docs/plan.md`](../../docs/plan.md) — so the public milestone closes on publicly provable facts:
  `core/` authored fresh, every engine-relevant constitution clause mapped to a home or a recorded
  deferral, and a real task run end-to-end on engine + this workspace. The half of the old criterion that
  depended on material outside this repository moved out of the plan and into its own context. _Because:_
  three of the four original clauses could not execute in a build session at all, and the criterion made
  material from outside this repository a required *input* to the engine — the opposite of how `core/`
  was actually authored (clean-room from the constitution and public practice) and of what
  [`../../core/README.md`](../../core/README.md) already claimed. A criterion that cannot be demonstrated
  is one that can only be asserted, which this build's own protocol forbids.
- **Findings from outside this repository flow one way only.** If a concept-coverage check performed in
  another context ever finds something the engine misses, that finding does not go into `core/`. It goes
  to the maintainer, who decides whether it belongs in the constitution; `core/` then covers it *from*
  [`../../docs/vision.md`](../../docs/vision.md), like every other clause. _Because:_ the direction of
  derivation is the whole point of the amendment above, and a single convenient exception would undo it.
- **The platform-floor proposal was accepted with administrators included**
  ([`../proposals/0001-platform-floor-on-main.md`](../proposals/0001-platform-floor-on-main.md)) —
  accepted, **not yet applied**.
- **The three workspaces stay distinct** — confirmed, as recorded in
  [`../memory/three-workspaces-not-one.md`](../memory/three-workspaces-not-one.md).
