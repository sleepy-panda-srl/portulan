## Demonstration 1 — a budget repaired by demotion, 2026-11-09

[#509](https://github.com/sleepy-panda-srl/portulan/issues/509) is demonstrated on an
[invented catalog project](../../cli/fixtures/context-budget/project/). Run from the repository root:

```sh
node cli/fixtures/generate-context-budget.mjs
```

The [recorded observations](../../cli/fixtures/context-budget/observations.json) are the figure carrier.
The instrument compiles an isolated copy, then runs the real context and static-doctor CLIs: both are
red while the always unit exceeds its declared budget, with context the doctor's only failing check.
It changes the unit to `on-read`, adds the routing description required there, and recompiles. The old
always target is removed, an index line points to the retained guidance, and both CLIs return green.
The manifest stays byte-identical throughout, and the guidance body's digest does not change.

The [context suite](../../cli/context.test.mjs) reproduces this JSON byte for byte and rejects a budget
raise, an absent demotion, a lost body and unrelated validation failures. Pack roots and the child
processes' empty host directory are pinned; static doctor reads no usage records. This is a synthetic
workspace with an explicitly invented ratio, so its token figures are estimates, not exact counts or
evidence of host calibration. It demonstrates neither host loading timing nor an upgrade, and the
milestone remains open.

## Demonstration 2 — path loading in a real host, 2026-11-09

[#510](https://github.com/sleepy-panda-srl/portulan/issues/510) is demonstrated by a
[normalized capture](../../cli/fixtures/on-path-host/capture.json) of an actual Claude Code run,
using the existing [invented guidance workspace](../../cli/fixtures/guidance/). Its actual host version,
default model, session, two prompts, Read calls, replies, observer events, source/target hashes and
raw-stream digests are recorded there. This is a real run with invented inputs, not a scripted host.

The manual instrument copies that workspace into canonical scratch, adds a random observation label
only to the copied on-path source body, and runs the actual compiler. The compiler's target retains
that body under `paths: ["api/**"]`. In one host process/session, the first prompt reads only
`docs/control.txt`; the reply is `NOT_LOADED`. The second reads only `api/orders.txt`; the host emits
an `InstructionsLoaded` event for the target with `load_reason: path_glob_match` and that API file as
its trigger, and the reply gives the previously undisclosed label. The completed capture has no
startup/include load of that target, has eager-load positive controls, and has unchanged fixture bytes.

For this observed host, the event reports its glob as `api`, while the compiler's frontmatter spells
`api/**`; both values are retained rather than rewriting the event. The
[host contract](https://code.claude.com/docs/en/hooks#instructionsloaded) makes instruction-load hooks
asynchronous and observational. Checks therefore use the completed record and causal reason/trigger
fields; callback append order is not treated as load order. Every started recorder completed and the
host exited successfully.

Scratch-local exclusions handle user and ancestor instruction paths separately from project-only
settings selection. Auto memory and skills are disabled and MCP configuration is strict and empty.
The observer emits no guidance; its separate Read guard denies alternate routes, which also invalidate
the capture. No unexpected outside activity was observed. These are recorded controls, not a claim to
measure the host's full context. The label is absent from prompts, settings, command arguments and
ordinary file data before the host run.

Run the [offline verifier](../../cli/fixtures/on-path-host/verify.mjs):

```sh
node cli/fixtures/on-path-host/verify.mjs
```

The [tests](../../cli/fixtures/on-path-host/verify.test.mjs) reject missing controls, startup loads,
wrong triggers/globs/sessions, altered or rehashed contradictory source/target data, alternate Reads,
label leakage, unfinished observers and failed host exits. Harmless asynchronous event reordering
passes. Offline checks establish artifact coherence; private raw streams remain available for the
independent checkpoint's comparison. A repeat live capture is explicit:

```sh
node cli/fixtures/on-path-host/capture.mjs --run-host /absolute/path/to/fresh-output-directory
```

It requires an authenticated host and uses the existing subscription. The live helper is in the
network-mode audit, refuses CI, and is never launched by verification. No automatic job was added.
This demonstrates this host run's path boundary; other hosts, token calibration and milestone closure
remain undemonstrated. Row 12 stays open.

## Demonstration 3 — the demo on bundle upgrade, 2026-11-09

For [#511](https://github.com/sleepy-panda-srl/portulan/issues/511), Marius ruled
“Bundle-upgrade evidence” on 2026-11-09: upgrading the bundle, with workspace
migration recorded separately. Run from the repository root:

```sh
node cli/fixtures/generate-demo-upgrade.mjs
```

The [observations](../../cli/fixtures/demo-upgrade/observations.json) carry both
byte rosters. The instrument materializes the complete unchanged fictional demo
in a scratch Combcount project, measures the v0.1.3 boot inputs, replaces those
inputs at the same bundle location with v0.2.0, and measures again. These are
diagnostic boot read-set bytes: one explicitly selected Combcount repo card and
the declared memory index, with record bodies and the other card left on-read.
Both pinned boot procedures support that selection. They are not observations
of host loading timing, exact token counts, or a host's installer.

| Pinned bundle | Bundle inputs | Workspace inputs | Boot read-set |
|---|---:|---:|---:|
| v0.1.3 | 25,671 B | 17,287 B | 42,958 B |
| v0.2.0 | 18,963 B | 17,287 B | 36,250 B |

The reduction is **6,708 B**, with no workspace configuration or content change.
The [input snapshot](../../cli/fixtures/demo-upgrade/inputs.json) preserves original
paths, exact UTF-8 bytes, lengths and SHA-256 digests, pinned to releases
[`43038826f31e85ec02e36e5cdea20376ac1b58cf`](https://github.com/sleepy-panda-srl/portulan/tree/43038826f31e85ec02e36e5cdea20376ac1b58cf)
and
[`78a30817a62d745307acedea6aae4fed6833d83c`](https://github.com/sleepy-panda-srl/portulan/tree/78a30817a62d745307acedea6aae4fed6833d83c).
Their complete `examples/` trees are byte-identical. The after roster is derived
by the current `bootReadSet` carrier against the materialized release inputs;
the legacy roster follows the old unsplit skill and kernel.

The real current `upgrade --write` CLI runs separately under an empty host. It
returns 0 and “owes nothing — current at 2.4”: the unchanged demo owes no applicable
workspace migrations, although the current bundle implements a later schema.
This command changes no workspace file and causes none of the reduction.
The [offline suite](../../cli/demo-upgrade.test.mjs) reproduces the observations

release provenance, corrupt bytes and selection drift. No model or network call
runs in this demonstration. Row 12 remains open.

## Drafting rationale — 2026-09-23

**Numbering and order ruled by Marius, 2026-09-23: *"Run before row 9. It's top priority."*** The row is
numbered 12 and appended, and nothing is renumbered, which is the precedent row 11 set. Its place in the
order is carried by its Status cell and by the Sequencing rationale, not by its number: row 9 multiplies
fresh contexts, and each one pays the always tier again, so the tier is priced first.

**The sessions column reads *1 per change*, not a total.** Proposal 0036 orders nine changes, one per pull
request. The last is a proposal of its own, and how many demotions Portulan's own footprint needs is set by
what the measurement finds, so a total written today would be a guess.

**Three demonstrations, each chosen to prove a different thing is real:**

- **A declared budget forced over is red, and a demotion returns it green.** The rail exists, and its
  remedy is the one the rule names. A raise in the same change is barred by doctrine, as it is for memory,
  and no checker establishes that one did not happen: [`../../spec/slots.md`](../../spec/slots.md) records
  the same limit for memory's budgets.
- **An on-path target loads when its path is first touched, and not before.** A compiled file at a path a
  human knows is not a tier. Row 7's parity clause learned this about skills: a count that reproduces from
  a directory with no workspace in it demonstrates nothing.
- **Portulan's own footprint and the demo workspace's boot read-set, measured before and after, the smaller
  figures arriving on upgrade.** That is the goal's clause *by installing or upgrading*, and the only one
  of the three an adopter would notice without reading a report.

**What the row leaves out, on purpose:**

- **The handoff series' size budget.** Ruled its own proposal, `0037`. Handoffs are an on-read cost, not an
  always-tier one, and a budget on the series total has every remedy barred. _(Settled when `0037` was accepted: by
  the maintainer's answer to its third question on 2026-09-23, the row carries that proposal's one demonstration as
  its fourth, a bound handoff forced over its cap red and compression returning it green, with the index's window
  holding its budget while the series grows; the rule stays argued in
  [`0037`](../../.portulan/proposals/0037-a-handoff-is-budgeted-where-it-is-written.md).)_
- **The adoption in the sealed repository.** It is private, and a milestone's exit criterion must be
  demonstrable from this repository alone
  ([`a-public-criterion-must-be-demonstrable-from-this-repo`](../../.portulan/memory/a-public-criterion-must-be-demonstrable-from-this-repo.md)).
  It gates nothing here.
- **A version number.** The manifest key needs a MINOR, and `2.9` is commissioned by
  [`0034`](../../.portulan/proposals/0034-one-spec-bump-carries-both-evals-and-telemetry.md) and not yet
  drafted. The row names no version, so it cannot pre-empt that choice. _(Settled when the key was drafted:
  it took `2.9` alone in [#440](https://github.com/sleepy-panda-srl/portulan/pull/440), since `0034`'s
  accepted text commissions one MINOR without naming its number; `0034`'s slots and `0038`'s keys take the
  next free MINOR.)_
