## Amendment — 2026-07-30 (an expansion) — DRAFTED, awaiting the maintainer's ratification

**Not yet applied to the row.** The text below is proposed; row 7 in [`../plan.md`](../plan.md) is

**Proposed row text, verbatim:**

> **Amended 2026-07-30 (an expansion; argument in [`milestones/m07.md`](m07.md)).** Added,
> with nothing removed: the CLI carries the **residence choice and the switch** that proposal
> [`0017`](../../.portulan/proposals/0017-one-repository-one-governing-workspace.md) rules on. `init` asks
> where this repository's workspace resides — in the repository, or in a workspace that names it — and
> writes a full workspace or a pointer accordingly. `vendor` performs the **switch** in both directions,
> feed-side ↔ in-repo, under the contract the proposal sets: the workspace is materialised in the new
> residence, a pointer or nothing is left in the old, and **`doctor` is green at both ends before the
> old residence is retired**. `upgrade` migrates a workspace in **either** residence. And a **fourth
> demonstration** joins the row's three: **parity** — the same workspace exercised in both residences
> with no functionality difference, and the switch run in both directions.

_**The two relative links above are re-based one directory deeper so they resolve from this file**, the
same convention this milestone's header describes for the material moved here in the post-M5
reconciliation. Applied to the row in [`../plan.md`](../plan.md) they become
`(../.portulan/proposals/0017-one-repository-one-governing-workspace.md)` and `(milestones/m07.md)`.
Every target is unchanged; only the number of `../` moves._

**Checked as an expansion, in the way the M1–M4 amendments established.** It adds deliverables to
`init`, `vendor` and `upgrade` — all three already named in the row — and a fourth demonstration beside
the row's existing three. Every existing clause stands unchanged; nothing is removed, narrowed or made
conditional.

**Why it lands here rather than in row 6.** Row 6 ships the feed and the portfolio workspace; the
residence *choice* is a thing the CLI does to a customer's repository, and this is the CLI's row. The
ruling itself is recorded and railed at row 6's edge — the pointer kind, and `doctor`'s refusals — so
what remains for row 7 is the mechanics: asking, switching, migrating, and demonstrating parity.

**Why parity needs a demonstration rather than an assertion.** The proposal's argument is that features
key to workspace *slots* and never to residence, which is checkable by reading the tools — but "no
functionality difference" is a claim about behaviour, and this project's own bar is that behaviour is
exercised rather than asserted (the verification hierarchy: compiles < tests pass < behaviour
exercised). One workspace, both residences, the same operations, and the switch run in **both**
directions — because a one-way switch demonstrated once is a migration, not a choice.

**One clause routed to the maintainer rather than ratified quietly: `vendor` as the switch's carrier.**
[`../vision.md`](../vision.md) glosses `vendor` as *"self-contained AGENTS.md + .portulan/ for any
host"*. Feed-side → in-repo is exactly that shape: materialising a self-contained workspace into a
repository is what the gloss describes. The **reverse** direction — in-repo → feed-side, producing a
workspace that ships as a plugin through a private feed — sits outside the gloss, and calling it
`vendor` stretches a word that currently means something narrower. There is no contradiction, and the
row becomes law once ratified, so the stretch is named rather than absorbed. Two ways to take it, and
the choice is the maintainer's:

- **Keep `vendor` for both directions**, on the reading that the operation is one operation —
  materialise this workspace *there* — and the direction is an argument to it rather than a different
  verb. The gloss then widens by one clause, which is a vision edit and therefore his.
- **Leave the subcommand unassigned in the row** — "the CLI performs the switch in both directions" —
  and let milestone 7's design settle which verb carries it, with `vendor` the candidate.

The text above takes the first, because a row that names no subcommand is a row that has deferred the
part a reader most wants; but the second is a one-line change to the proposed text and costs nothing if
he prefers it.
