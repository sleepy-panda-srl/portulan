## Amendment — 2026-07-29 (a NARROWING)

**Criterion amended with Marius, 2026-07-29, this row only — and it is the first amendment here that is a NARROWING, so it is argued as one rather than checked as one.** The clause *"mines incidents and pull-request reviews into **draft proposals**"* now reads *"into **candidates a human files as proposals**"*. **The letter of the original was demonstrated unbuildable, and demonstrated is the operative word** — the M3 `skills-ref` precedent's method, where the tool was **run first** and only then reworded around. Run here on a scratch copy of this tree: a proposal carrying every field a deterministic pass can derive — numbered filename, incident link, evidence, a recorded outcome — was written into `.portulan/proposals/` and [`../.portulan/verify/docs.sh`](../../.portulan/verify/docs.sh) went **RED on exactly one thing**, `1 proposal(s) name no pull request`, with the control green before and the other two proposal assertions passing. That is not a limit of this implementation: **the pass writes its files before the pull request that carries them exists, and has no update path by design** (an update push raises `synchronize` from `GITHUB_TOKEN`, which starts no runs, so updating would take a mergeable pull request and make it unmergeable). A generated proposal can therefore *never* name its filing pull request, and a scheduled pass that wrote one would red its own pull request on the rail this milestone shipped one session earlier. **The clause was refuted by a check the same milestone built** — which is the compounding loop this constitution bets on, turned on the row that commissioned it, and is the reason this rewording is evidence rather than convenience. **Why a narrowing is nonetheless the right repair, stated because the direction is the dangerous one.** The alternative was to retire the attestation that makes unattended filing safe: the pass composes no prose at run time, so every string it emits is a literal from a reviewed, seam-scanned file or a value derived from the tree, and *a diff with no new prose cannot carry a new seam hit*. Authoring a proposal's altitude and its retirement condition is authorship about work the pass cannot read — it would put unreviewed sentences into a public repository on a cron, and the filing design's whole safety argument would have to be rebuilt. Put to Marius as exactly that trade rather than resolved by the implementer, per [`../.portulan/memory/a-doctrine-promise-belongs-in-the-row-it-names.md`](../../.portulan/memory/a-doctrine-promise-belongs-in-the-row-it-names.md); he kept the attestation. **What is given up is named rather than glossed:** a candidate is a pointer with evidence, not a fillable draft, so the human still writes the argument — and `evolution.md`'s promise that the backlog is drafted *for* the human rather than *by* them is kept at the level of the backlog, not of the document. **The sibling carriers moved in the same change and the grep was re-run in both directions afterwards**, which is what the milestone-4 precedent requires of a reconciliation: `core/operating/evolution.md`, `core/skills/codify/SKILL.md` (whose *"same output shape"* would have been false), `core/personas/librarian.md`, `core/operating/memory.md` and `core/operating/loop.md` all state the candidate/proposal split, and no sentence in `core/`, `spec/`, `cli/`, `agents/`, `plugin/` or this workspace still says the half is unbuilt. **This does not touch the consolidation clause**, which is delivered as written.
