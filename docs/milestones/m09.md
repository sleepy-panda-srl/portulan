> **The row is the law; this file is the legislative history.** Row 9 of the milestone table in
> [`../plan.md`](../plan.md) carries the binding criterion — this milestone is still open, so there is
> no signed verdict yet — and this file deliberately does not restate the criterion: a rule with two
> carriers is obeyed at the narrower one, which is the defect this repository names more often than
> any other.
>
> What follows stood **inside that row** until the post-M5 reconciliation moved it here, and it is
> relocated **verbatim**: amendment arguments with their expansion/narrowing verdicts, session notes,
> and the close-evidence narrative, each as it was written and reviewed. The only edit is that
> relative links are re-based one directory deeper so they still resolve — every target is unchanged,
> and each re-basing is enumerated in the pull request that moved it.

## Nothing has been relocated here, and that is the record

**This milestone has no legislative history yet.** It has never been worked: no session has opened
against it, its criterion has never been amended, and it has no close to carry evidence for. So the
post-M5 reconciliation had nothing to move out of row 9, and this file holds nothing.

It exists anyway, and the reason is the one the maintainer gave when milestones 0 and 1 were given
theirs: **a gap in this directory reads as an exemption.** A reader walking the milestone table finds
a file behind every other row, and the absence of one behind this row invites the inference that some
rows are exempt from carrying their history — which is exactly the reading the split was designed to
prevent at the Status column. Declaring the absence costs one file; leaving it to be inferred costs
the property.

That is the same discipline the verify recipes already practise on their own output: *nothing to
report* and *did not look* must never print the same way. An empty file here says **nothing to
report**. No file at all would have said neither.

## What will land here

The first session that opens against milestone 9 writes its session note here, not into the row —
[`../../.portulan/verify/docs.sh`](../../.portulan/verify/docs.sh)'s `plan` check refuses
`[Ss]ession N of` inside a milestone-table row, so the row cannot take it even by accident. Any
amendment to the criterion brings its argument and its expansion-or-narrowing verdict here, leaving
the operative wording in the row. The close leaves its evidence narrative here and a signed one-clause
verdict in Status.

Until then this page is correct as it stands, and it should not be padded to look busier than the
milestone is.
